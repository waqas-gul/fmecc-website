# FMECC Website — Architecture

Code structure, boundaries and contracts for the FMECC site. Read with [MASTER_PLAN.md](./MASTER_PLAN.md) and [DESIGN.md](./DESIGN.md). Rules for day-to-day work are in [CLAUDE.md](../CLAUDE.md).

## 1. Stack and verified facts

| Item | Decision |
|------|----------|
| Framework | Next.js 16.4.3, App Router, Turbopack (default), React 19.3, TypeScript 5.9 strict |
| Styling | Tailwind CSS v4 through the `@tailwindcss/turbopack` loader rule in `next.config.ts`; tokens in `src/shared/styles/tokens.css` (approved palette and semantic tokens: DESIGN.md §2) |
| Output | **Static export** (`output: 'export'`) to `out/`, deployable to any static host |
| Animation | `gsap` (+ `ScrollTrigger`, `SplitText` — bundled and free in gsap ≥ 3.13) from `@/shared/lib/gsap` for scroll choreography only; the Web Animations API with IntersectionObserver for fade-up reveals (`Reveal`); native `<details>` with CSS for the accordion; CSS transitions for the header; React 19.3 `ViewTransition` for route transitions. `motion` (`motion/react`) stays approved for future layout animation but is currently imported nowhere (WS-6) |
| 3D | `three`, `@react-three/fiber` (v9, React 19 compatible), `@react-three/drei` (v10), `@types/three` |
| Icons | `lucide-react` (already in Next's default `optimizePackageImports`) |
| Images | `next/image` with a custom loader + `scripts/optimize-images.mjs` using `sharp` (present as a Next dependency; declare it explicitly as a devDependency) |

Facts verified against the installed Next 16.4.3 docs (`node_modules/next/dist/docs/`) and a throwaway export build:
- `output: 'export'` **fails** when `cacheComponents` is enabled ("Invariant: PPR cannot be enabled in export mode"). The scaffold's `cacheComponents` and `partialPrefetching` flags are removed in Phase 0.
- With `cacheComponents` off and export on, `robots.ts`, `sitemap.ts` and generated `opengraph-image.tsx` must `export const dynamic = 'force-static'`; static files (`robots.txt`, `sitemap.xml`, `opengraph-image.png`) also work.
- Dynamic routes need `generateStaticParams()`; `typedRoutes: true`, `trailingSlash: true` and a custom image loader all work in export mode (the build emitted `<folder>/index.html` and correct `srcset`s).
- `next lint` is gone: lint with `eslint .`. Type-check with `next typegen && tsc --noEmit`; typegen provides the global `LayoutProps<'/'>` and `PageProps<'/services/[slug]'>` helper types.
- `next/image`: `priority` is deprecated, use `preload`.
- `next/dynamic` with `ssr: false` is only allowed inside Client Components.
- `useSearchParams()` in a statically exported page must sit inside a `<Suspense>` boundary.
- Without `cacheComponents` there is no Activity-based route preservation: routes unmount normally, so effect cleanup is sufficient for GSAP and three.js.
- `AGENTS.md` is regenerated by `next dev`; keep its block committed.
- `package.json` declares `sideEffects` (CSS and `src/shared/lib/gsap/gsap.ts`). Without it the `@/shared/ui` barrel put GSAP on every page (measured in WS-0). Any new module with top-level side effects must be added to that list.
- Measured baseline: Next 16.4 + React 19.3 + Turbopack runtime ≈ 173 KB gz of JS on every route before any app code.

## 2. Feature-Sliced rules

Layers, top to bottom. A module may import only from layers **below** it, never sideways within the same layer, and only through a slice's `index.ts`.

| Layer | Contains | May import |
|-------|----------|------------|
| `app` | Routes, layouts, metadata, route files. Thin: compose widgets, pass entity data | widgets, features, entities, shared |
| `widgets` | Page sections and chrome (`SiteHeader`, `HomeHero`, `ServiceScope`) | features, entities, shared |
| `features` | User interactions with business meaning (`QuoteRequestForm`, `ProjectFilter`, `ContactChannels`) | entities, shared |
| `entities` | Domain types, static data and small display primitives (`Service`, `services`, `ServiceCard`) | shared |
| `shared` | Design-system UI, config, libs, 3D runtime, styles, types. No domain knowledge | shared only |

Conventions
- Slice folders are kebab-case; components are PascalCase files; each slice exports a public API from `index.ts` and nothing else is imported from outside the slice.
- Segments inside a slice: `ui/`, `model/` (types, selectors), `data/` (static content), `lib/` (helpers). Use only what the slice needs.
- Cross-slice needs are solved by lifting to a lower layer (usually `shared/types` or `entities`), not by cross-importing.
- Path alias `@/` → `src/`. Imports are ordered: react/next, packages, `@/shared`, `@/entities`, `@/features`, `@/widgets`, relative.
- Before creating a component, search `src/shared/ui` and the target layer; duplicates are rejected in review.

## 4. Component boundaries

| Question | Answer |
|----------|--------|
| Is it a page section with layout and content? | `widgets/<section>` |
| Does it handle user input tied to a business goal (form, filter, contact action)? | `features/<name>` |
| Is it a domain object's type, data or a card that renders that object? | `entities/<domain>` |
| Is it generic UI, a hook, config or a utility with no domain words in it? | `shared/*` |
| Is it only route wiring, metadata or `generateStaticParams`? | `app/*` |

Widgets compose entities and shared UI; they do not define domain types. Features own their state and expose a single component plus optional helpers. Entities never import features or widgets. `shared/ui` components accept `className` and forward refs where DOM access is plausible (animation targets).

## 5. Server versus client component strategy

Default to Server Components. Mark a file `'use client'` only for state, effects, browser APIs, GSAP, Motion, three.js or event handlers. Keep client files small; render content on the server and wrap with client "motion islands" that take `children`.

| Server | Client |
|--------|--------|
| All `app/` pages and layouts, `Section`, `Container`, `SectionHeader`, `Eyebrow`, `Card`, `Badge`, `Breadcrumbs`, `Stat`, `MediaImage`, `IconTile`, `Accordion` (native `<details>`), `ServiceCard`, `ProjectCard`, `ContactChannels`, `SiteFooter`, `CtaBand`, `PageHero`, all `service-detail` and `project-detail` sections | `SiteHeader` (scroll and menu state), `Reveal`, `VideoBackground`, `QuoteRequestForm`, `ProjectFilter`, `LazyScene` and scenes, `HomeHero` motion layer, `ServicesShowcase` switcher, `FeaturedProjects` gallery, `ProcessSection` scrub |

Rules
- Client components receive serializable props only (no functions, no class instances, no React elements other than `children`).
- No `window`/`document` access at module scope; use effects. React 19 no longer warns about `useLayoutEffect` during prerender, so it is fine for GSAP setup.
- `next/dynamic(..., { ssr: false })` is used only inside client components (`LazyScene`).
- Animation targets are reached through refs or `data-animate` attributes inside a `gsap.context` scope; never by global selectors.
- Every client component cleans up: `ctx.revert()`, `ScrollTrigger.kill()`, three.js `dispose()`, observers disconnected.

`LazyScene` renders the poster immediately; when the element is within one viewport, WebGL is available, motion is allowed and `tier !== 'low'`, it dynamically imports the scene and cross-fades it in. Scenes live next to the widgets that use them (`widgets/service-showcase/scenes/*`) so `shared` never imports domain visuals. A `SceneLoader` is a function: export loaders from a `'use client'` module so Server Components can pass them to client components. `SceneCanvas` is itself lazy-loaded, so importing `@/shared/three` never adds three.js to a route.

## 9. Routing approach

- File-based routes exactly as in §3; `trailingSlash: true` so every route is `<folder>/index.html`.
- `services/[slug]` and `projects/[slug]` export `generateStaticParams()` from entity registries and call `notFound()` for unknown slugs; `generateMetadata` is static (reads entity data only).
- Export fails when a dynamic segment generates no params, so while `projects` is empty the detail page lives in the private folder `projects/_detail/` (linted and type-checked, not routed). Adding the first verified project requires `git mv src/app/projects/_detail "src/app/projects/[slug]"`; the `/projects/` build check (`projects/_lib/check-portfolio.ts`) stops the build until that is done.
- `typedRoutes: true`: all `href`s are typed; `routes.*` helpers are the only place route strings are built.
- Metadata: `app/layout.tsx` sets `metadataBase`, default title/template, Open Graph defaults; pages call `buildMetadata()`.
- Route transitions: wrap `{children}` in `app/layout.tsx` with React 19.3 `<ViewTransition default="none">` and give page roots a short cross-fade class; scroll resets to top on navigation (default behaviour).
- Query-driven UI (`?service=`) is client-only behind `<Suspense>`; the server-rendered default state must be correct without the query.
- No route handlers, server actions, middleware/proxy, redirects, rewrites or headers (unsupported in export mode).

## 10. Static-export considerations

Target `next.config.ts` (Phase 0):
```ts
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  output: 'export',
  trailingSlash: true,
  typedRoutes: true,
  reactStrictMode: true,
  images: {
    loader: 'custom',
    loaderFile: './src/shared/lib/media/image-loader.ts',
    deviceSizes: [640, 960, 1280, 1600, 1920],
    imageSizes: [320, 480],
  },
  turbopack: { rules: { '*.css': { loaders: ['@tailwindcss/turbopack'], as: '*.css' } } },
};
export default nextConfig;
```
Checklist
- Remove `cacheComponents` and `partialPrefetching` (incompatible with export; verified).
- `robots.ts`, `sitemap.ts` and any generated metadata image export `dynamic = 'force-static'`.
- Every dynamic segment has `generateStaticParams()` returning every slug; placeholder projects are included during development and must be removed before launch.
- Images: no default loader; the custom loader maps to pre-generated WebP files. Brand assets use `unoptimized`.
- Forms post to an external endpoint or fall back to `mailto:`; no server code.
- Build with Turbopack (default). Do not use `next build --webpack`; Tailwind is wired through the Turbopack loader rule.
- `npm run build` ends with `scripts/fix-export-segments.mjs`. The client router prefetches each segment from a flat file such as `services/<slug>/__next.services.$d$slug.__PAGE__.txt`, but Next 16.4.3 derives that name with `path.relative()`, so a Windows build writes nested folders (`__next.services/$d$slug/__PAGE__.txt`) and every nested route logs 404 prefetches. The script moves those files to the flat names; on Linux and macOS it finds nothing to do. Re-check after a Next upgrade and drop it once the export is fixed upstream.
- Hosting: upload `out/`; configure `404.html` as the not-found page; ensure the host serves `<folder>/index.html` for `/<folder>/`; set long cache headers for `/_next/static/*` and `/images/*` at the host.
- Environment: `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_FORM_ENDPOINT`, `NEXT_PUBLIC_ANALYTICS_ID` are read at build time only.

## 13. Integration approach

1. **Contract freeze**: WS-0 ends with every export in §6–§8 present (stubs allowed, typed exactly). From then on a contract change is a PR that edits ARCHITECTURE.md and every consumer in the same change.
2. **Branches**: `ws/<name>` off `master` (the integration branch); rebase daily; small PRs; one PR must not touch another stream's directories except through the WS-6 audit path.
3. **Gate**: every PR runs `npm run check` (`eslint .`, `next typegen && tsc --noEmit`, `next build`) and a manual route check from `out/`.
4. **Decoupling points**: `LazyScene` stub returns the poster until WS-5 lands; `ServiceShowcase` falls back to the gallery when a scene is missing; `FeaturedProjects` and `RelatedProjects` render nothing when data is empty; `ContactChannels` omits null channels. Streams never block on each other's content.
5. **Merge order**: WS-0 → WS-1..4 in any order → WS-5 → WS-6. Phase 4 hardening runs on `master`.
6. **Conflict policy**: if a stream must touch a foreign file, the change is additive, minimal and called out in the PR description; the owning stream reviews it.
